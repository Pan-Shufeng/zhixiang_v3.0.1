# 知向 × DSH：Windows x64 构建

此文件供源码构建者使用。同学使用 Release ZIP 时只需完整解压并双击 `启动知向联网版.cmd`，无需安装 Python、Node.js、Docker 或 pnpm。

## 固定版本与构建顺序

- Windows x64；Python 3.13.15 嵌入版，Node.js 24.19.0 官方 ZIP；构建机需 Python、Node.js 与 pnpm 11。
- `dsh/package.json` 和 `dsh/pnpm-lock.yaml` 固定 DeepSeek Harness `0.1.7-rc.2`；`dsh/search.mjs` 调用上游原生搜索提供方，`dsh/zhixiang.patch.yml` 配置 DSH MCP 客户端。
- `frontend/package.json` 与 `frontend/pnpm-lock.yaml` 固定网页依赖。

在仓库根目录按顺序执行：

```powershell
py -3 packaging/prepare_runtime.py
py -3 packaging/prepare_node.py
py -3 packaging/prepare_dsh_flat.py
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run build
py -3 packaging/build_package.py --trial-env <你明确授权分发的试用配置文件>
```

`prepare_runtime.py` 与 `prepare_node.py` 下载官方 ZIP、核对写在脚本中的 SHA-256；`prepare_dsh_flat.py` 按锁文件构造无链接的可打包依赖目录。构建脚本只把授权试用 Key 放进 ZIP 内的 `config/trial.json`，源码不含 Key；使用者可在应用中改用自己的 Key。`--trial-model` 可指定实际可用的模型，默认 `deepseek-v4-pro`。当前发布构建要求显式提供有效试用配置；如另行分发无 Key 包，应修改构建配置并重新验证。

输出为 `交付/知向_DSH集成版_Windows体验包.zip`，构建清单为 `packaging/last_build.json`。不会覆盖旧 `交付/知向联网版_Windows体验包.zip`；不会复制开发目录的 `data`、个人 `config/local.json`、日志或 DSH 会话。第三方文章/PDF 的全文不随包再次分发，公开案例只提供来源目录和作者简述。

## 验证与边界

运行 `py -3 packaging/verify_dsh_portable.py`，脚本会把最终 ZIP 解压到全新、含中文和空格的目录，用包内启动脚本验证网页、原生搜索、原文读取及判断持久化。它会如实记录“候选 URL 不可读时改用明确的发布者链接”的手动补源，不把补源误报为搜索候选已读成功。DSH 客户端工具调用、7+1 题的语义检查和界面录像需另外验收。旧 `verify_portable.py` 只服务于旧联网版 ZIP。代码编译、ZIP 生成或 MCP 列工具本身均不代表联网搜索已验收。试用额度耗尽、网络不通或网页拒绝抓取时要显示真实失败，不使用内置案例冒充实时结果。每次重新构建后都应复测最终 ZIP。
