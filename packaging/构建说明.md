# Windows 体验包构建

此目录供作者构建与验证使用，体验者无需执行这里的构建步骤。

## 文件边界

- `prepare_runtime.py`：从 python.org 下载固定的官方 Python 3.13.15 x64 嵌入版，并对照发布页 SHA-256 核验；构建时将后端依赖作为应用组件放入独立运行环境。
- `launcher.py`：启动、检测及停止本地知向，不根据端口或进程名强制结束程序；只有本目录启动记录、应用身份与进程号均匹配，才能发送带随机令牌的停止请求。
- `build_package.py`：从已完成的前后端和公开资料构建干净包。只在构建过程中读取作者授权的试用配置，不输出密钥。不复制 data、logs、config/local.json 或旧 Open Notebook 数据。

## 构建顺序

1. 在作者开发环境执行 `prepare_runtime.py`；这是下载发生的位置，体验包启动不再安装依赖。
2. 按前端开发流程完成 `frontend/dist`，确认后端及 `assets` 的公开预置材料已经准备好。
3. 执行 `build_package.py`。默认输出到 `交付/知向联网版_Windows体验包.zip`，构建记录保存在 `packaging/last_build.json`。联网模块 `backend/search_web.py` 随包分发，开发诊断脚本不进入体验包。`--trial-model` 默认 `deepseek-v4-pro`，只影响新体验包内的试用配置，不修改共享 env 文件；不要依赖共享 env 中旧的 flash 型号。`prepare_variant.py` 使用相同默认值，重新初始化也不会默认回退 flash。
4. 将 ZIP 解压到一个新的中文及空格路径，使用包内启动文件验证实际启动、离线导读、来源打开、保存重载、停止和再次启动。前后端更新后应重新构建最终 ZIP，再验证最终交付物。

发布前不得把工作目录已经形成的判断历史或用户配置复制进 `assets`。试用配置是用户明确授权随课堂体验包分发的唯一密钥配置，其位置限定为 `config/trial.json`。

本版默认端口 8186，应用身份为 `zhixiang-web`，与原版 8176 分开。`verify_portable.py` 使用 8189，在中文及空格解压路径、移除开发工具 PATH 的环境验证启动、真实公开搜索与读取、零模型调用的案例导读、判断保存、重启与停止。Tavily 用户密钥不进入体验包；未配置时使用公开 Bing RSS 入口，搜索质量与可达性取决于外部服务。

验证脚本默认检查包内模型为 `deepseek-v4-pro`（可通过 `--expected-model` 明确覆盖），并扫描实际解压文件，确认试用密钥只存在于 `config/trial.json`。这项便携检查不调用 AI；真实 pro 年报分析的独立记录见 `验收/录像前_模型恢复核验.md`。录制文件单独交付，不装入程序 ZIP。
