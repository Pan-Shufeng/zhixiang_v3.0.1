# 知向 · 多客户端连接版（v3.1.1）

知向帮助你围绕一个商业问题**找公开依据、核对原文、保存自己的判断，再用新材料检验它**。可以只用独立网页；也可以在 DeepSeek Harness（DSH）对话中调用同一份知向资料与判断。

v3.1.1 新增“连接 AI 客户端”：Codex / WorkBuddy 可备份并合并本地 MCP 配置、移除本连接；已有 DSH 可加载独立连接层启动。客户端调用时按需启动知向；`zhixiang_open_workspace` 返回可在内置浏览器打开的本机网页。客户端界面未改造，资料与判断共用。支持情况与真实验证边界见 [连接验收](连接验收.md)。

## 第一次使用：只需三步

本体验包面向 **Windows 64 位电脑**。不需要自己安装 Python、Node.js 或 Docker。

1. 打开 [v3.1.1 下载页](https://github.com/Pan-Shufeng/zhixiang_v3.0.1/releases/tag/v3.1.1-connect)，在页面下方 **Assets** 中下载 **`zhixiang-v3.1.1-windows.zip`**。不要下载旁边自动生成的 `Source code (zip)`：那是给开发者看的源码，没有现成的运行环境和课堂试用配置。
2. 对下载的 ZIP 右键选择“全部解压”，打开解压后的文件夹。**不要在压缩包预览窗口里直接双击 CMD**，也不要只单独复制某个 CMD 出来。
3. 双击 **`启动知向联网版.cmd`**，等待浏览器打开知向。如果没有自动打开，在浏览器输入 <http://127.0.0.1:8186>。结束使用时双击 **`停止知向联网版.cmd`**。

如果你只想用知向网页，其他 CMD 都不用点。首次打开可先看包内的 `先读我.txt`；下面是完整操作方法。

### 五个 CMD 文件分别做什么

| 文件 | 什么时候点 | 打开后做什么 |
| --- | --- | --- |
| **`启动知向联网版.cmd`** | 每次想用知向网页时 | 启动本机服务并打开网页。普通使用从这里开始。 |
| **`停止知向联网版.cmd`** | 今天用完时 | 关闭这份知向的本机服务。只关浏览器标签页不会停止服务；已保存的资料不会因此删除。 |
| **`连接我的AI客户端.cmd`** | 已有 Codex、WorkBuddy 或自己安装的 DSH，想在 AI 对话里调用知向时 | 启动知向并打开“连接 AI 客户端”页面；按页面指引选择你的客户端。没有这些客户端就不用点。 |
| **`启动DSH对话.cmd`** | 想试体验包自带的 DSH 对话时 | 打开独立的 DSH 对话页面，让它通过知向工具访问同一份本机资料。它和知向网页是两个页面。普通使用不需要。 |
| **`启动知向MCP.cmd`** | 需要手动给其他支持 MCP 的 AI 客户端配置知向时 | 作为客户端配置里的后台启动命令使用，**不要直接双击来找网页**。可参考 [`MCP配置示例.json`](MCP配置示例.json)；非开发者通常用上一行的“连接我的AI客户端”即可。 |

### 跟着做一次：从问题到自己的判断

1. 在首页点击 **“开始一个问题”**，输入自然语言问题，例如“东方甄选最近的经营状况如何？”；点击 **“搜索公开来源”**。联网搜索会使用模型额度，搜索到的只是网址线索。
2. 在 **“联网线索”** 查看标题、发布者、日期和摘要，点来源标题可去发布方网页核对；勾选值得看的来源，点击 **“读取原文并分析”**。知向只分析实际读到的材料；读不到正文的来源会标出来。也可以用 **“补充材料”** 加入公开链接或自己粘贴的原文。
3. 进入 **“看清问题”** 看分析及信息缺口，再到 **“查看依据”** 打开对应资料和原文。注意区分资料事实、AI 推断和仍需核实的问题。
4. 在 **“我的判断”** 写下**自己的**当前看法和待核实问题，点 **“保存我的判断”**。这一步需要你主动保存，AI 不会替你确认结论。
5. 过一段时间想复查时，从左侧 **“我的判断”** 打开原问题，点 **“继续找依据”** 或 **“补充材料”**。加入新资料后到 **“新变化”** 看它是支持、补充条件还是挑战原判断，再决定是否修改并保存新版本。

这些内容保存在**这台电脑上当前解压目录**的 `data/` 中；不要删除或随意移动整个文件夹，否则历史资料或 AI 客户端连接路径可能找不到。分享给其他人时，请发 GitHub 上的原始 ZIP，不要把自己用过的 `data/`、`config/` 文件夹再打包给别人。

### 想在已有 AI 客户端里使用

双击 **`连接我的AI客户端.cmd`** → 在打开的页面选择 **Codex / WorkBuddy / 已有 DSH** → 按页面完成连接 → 重启客户端连接或新开对话 → 复制页面提供的试用语句，让 AI 调用知向工具。首次工具调用若出现权限提示，按客户端的正常提示决定是否允许。连接并不改造客户端界面；AI 可以操作同一份知向资料，想看完整页面时让它“打开知向”，或直接打开本机网页。连接只适用于**同一台 Windows 电脑上的本地客户端**，不能让云端聊天网站直接访问你电脑上的知向。当前各客户端实际验证范围见 [连接验收](连接验收.md)。

### 打不开或搜不到时

- **双击后提示缺少运行环境／文件**：先确认下载的是 Assets 中的 `zhixiang-v3.1.1-windows.zip`，并已完整解压。
- **浏览器没有自动打开**：手动访问 <http://127.0.0.1:8186>。若仍打不开，查看 `logs/server.log`；若端口已被占用，先确认是否已经启动了另一份知向。
- **联网搜索没有结果**：确认电脑能上网，再查看页面中的具体失败信息和左下角 **“体验与设置” → “搜索来源”**。默认搜索依赖 DeepSeek 课堂试用额度与外部搜索服务；也可按页面选择公共搜索，或填自己的搜索／模型配置。公共搜索也可能限流，不能保证每个问题都有公开材料。你还可以换更具体的关键词，或用 **“补充材料”** 加入可信的公开链接。
- **关了网页但程序还在**：双击 `停止知向联网版.cmd`；下次再双击启动文件即可。

更详细的说明见 [`使用说明.md`](使用说明.md)。搜索流程的历史实测及局限见 [真实验收报告](验证报告.md)，本次连接实测见 [连接验收](连接验收.md)。

ZIP 内置 Python、Node.js、固定版本 DSH，以及作者明确授权的课堂试用 DeepSeek Key；**源码仓库不存该 Key**。试用额度耗尽或账户拒绝时，在线搜索与模型分析会停止，已有材料和判断仍可打开；使用者也能在页面里配置自己的 DeepSeek Key。开源不代表外部 API 免费，也不承诺账户绝不会发生费用。

## 三条真实入口，共用一份数据

- **独立网页**：自然语言问题调用 `@deepseek-ai/dsh-web-search-deepseek` 固定版本的原生搜索组件。它返回结构化 URL 候选；知向读取选中的网页原文、记录来源、组织证据与缺口，保存用户判断及版本，比较后来加入的新材料。
- **DSH 对话**：官方 DSH Web 配置 `@deepseek-ai/dsh-mcp-client`，通过本项目 MCP 工具读取和修改同一个知向后端。DSH 自己的 `web_search` 仍属于 DSH；知向工具负责来源入库、分析、判断版本和比较。两个网页是独立页面，不冒充嵌入式同一界面。
- **其他 MCP 客户端**：`启动知向MCP.cmd` 提供相同本地工具，包括搜索、列问题、读问题/来源、导入来源、分析、保存用户确认的判断和比较。连接示例在 `MCP配置示例.json`。

搜索结果只是候选，模型正文不会被当成搜索来源。网页无法读取时会明确失败；保存判断要用户确认，比较建议不会静默覆盖旧判断。来源域名、标题和摘要不等于事实核验。没有可核验的经营数据时，知向不能凭空给出营收。

## 源码、模型与数据

- `dsh/package.json` + `dsh/pnpm-lock.yaml`：DSH `0.1.7-rc.2`，其中独立网页使用官方原生搜索提供方，DSH 对话使用官方 MCP 客户端。固定版本可能因上游开发预览更新而需要迁移。
- `dsh/search.mjs`：调用官方 DSH 搜索提供方的薄适配层；当前原生搜索请求使用 `deepseek-v4-flash`，只读取结构化搜索结果，不抓取模型正文里的链接。知向资料分析的课堂试用配置为 `deepseek-v4-pro`；两个调用都使用同一 DeepSeek 账户额度，使用者改填个人 Key 后会沿用其账户。
- `backend/search_web.py`：候选格式、初步相关性和可选公共搜索/Tavily；`backend/server.py`：本地数据、原文读取、分析、判断与历史；`backend/mcp_server.py`：stdio MCP；`frontend/src`：React 网页。
- 数据在解压目录 `data/`，个人配置在 `config/`，日志在 `logs/`。搜索问题发往 DeepSeek 或用户主动选择的搜索服务；被选中的网页由本机读取；分析把原文片段与问题发往配置的模型服务。DSH 会在本机 `data/dsh-home/` 保存它自己的会话。没有把个人 `data/` 打进发布包。
- 内置案例在公开包中只有作者整理的来源目录与说明；完整第三方文章/PDF 不随包再次分发。阅读原件需打开发布者网址。

## 从源码构建

Windows x64、Node.js 24.19.0、Python 3.13.15、pnpm 11（或兼容版本）。按 [构建说明](packaging/构建说明.md) 准备内置 Python、Node 和固定版本 DSH 依赖，再构建前端；最后显式提供获授权的试用配置运行 `py -3 packaging/build_package.py --trial-env <配置文件>`。它生成新的 DSH 集成 ZIP，不覆盖旧联网版 ZIP。
